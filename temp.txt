def select(self, all_schemas, question, available_tables, pinned_tables=None, token_log=None):
    if pinned_tables:
        return pinned_tables, "Tables manually pinned by user.", question  # ← add question as enriched fallback

    if len(available_tables) == 1:
        return available_tables, f"Only one table available: '{available_tables[0]}'.", question

    try:
        response  = self._chain.invoke({"all_schemas": all_schemas, "question": question})
        if token_log is not None:
            token_log.append(_extract_tokens(response))
        text      = response.content.strip()

        t_match   = re.search(r"TABLES:\s*(.+)",         text, re.IGNORECASE)
        r_match   = re.search(r"REASONING:\s*(.+?)(?=ENRICHED_QUERY:|$)", text, re.IGNORECASE | re.DOTALL)
        e_match   = re.search(r"ENRICHED_QUERY:\s*(.+)", text, re.IGNORECASE | re.DOTALL)

        raw_tables     = t_match.group(1).strip() if t_match else ""
        reasoning      = r_match.group(1).strip() if r_match else ""
        enriched_query = e_match.group(1).strip() if e_match else question  # ← fallback to original

        selected = [t.strip() for t in raw_tables.split(",") if t.strip()]
        valid    = [t for t in selected if t in available_tables]

        if valid:
            return valid, reasoning, enriched_query  # ← now returns 3 values

        raise ValueError(f"Table selector returned no valid table names from response: {text!r}")

    except ValueError:
        raise
    except Exception as exc:
        raise RuntimeError(f"Table selection failed: {exc}") from exc

You are a data analyst assistant. Select the minimum set of tables needed to

Each table entry shows:
  INTERNAL_NAME | display: [dbo].[ActualName] | (N rows) | columns: col1, col2, ...

Selection rules (apply in order, stop at first match):
1. If one table contains ALL needed columns → use only that table.

3. If multiple tables could work → prefer the one whose name or columns most
   closely match the user's wording. Commit to that choice — do not alternate.
4. Never include a table "just in case" — only include if directly needed.
5. Use ONLY the INTERNAL_NAME (before the | symbol) in your response.

Return ONLY this format — nothing else:

TABLES: internal_name1,internal_name2
REASONING: <2-3 sentences explaining which tables you chose and why>
ENRICHED_QUERY: <
  Interpret what the user truly wants — not just what they literally said.
  Resolve ambiguous terms (e.g. "top", "best", "distribution", "performance")
  by mapping them to concrete operations available in the schema.
  
  Your enriched query must answer all of these internally before writing:
  - What is the user's core intent? (rank, count, compare, trend, filter, summarise)
  - What entity are they asking about? (map to the most relevant table + primary column)

  If the question is already fully unambiguous and maps directly to the schema

  Do NOT mention table names in bracket format here — use natural names.
  Do NOT write SQL — write a precise natural language specification.
